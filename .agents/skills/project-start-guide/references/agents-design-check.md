# AGENTS.mdへの追記テンプレート

設計資料と実装前の確認ルールを、実装するAIへ引き継ぐときに使う。以下のコードブロックが、対象プロジェクトの `AGENTS.md` に書き込む文面である。

## 統合するとき

- `docs/project-design.md` を、実際の設計資料のプロジェクトルートからの相対パスに置き換える。資料が複数ある場合は、必要な参照先を列挙する。
- 対象範囲に適用されるプロジェクト内の `AGENTS.md` に追加する。既存ファイルがなければ作成する。プロジェクト外やユーザー共通の指示は変更しない。
- 既存の指示を保つ。同等の節があれば必要な部分を統合し、同じルールを重複させない。
- ブロックの文面を直接書き込む。インストール済みSkillやこのreferenceへのリンクだけを残さず、別環境でも参照できるプロジェクト内の資料を指定する。
- 書き込み後に読み返し、参照先が存在すること、既存の指示との矛盾や重複がないことを確かめる。

## 書き込む文面

```markdown
## 実装前の設計確認

実装・挙動変更の前に、プロジェクトルートから見た `docs/project-design.md` の対象要件、設計、実装前確認を読む。以前の確認済みという記録だけで判断せず、今回の対象範囲を最新の資料と照合する。

- 今回の実装に影響する要件、外から見える正常時・失敗時の挙動、主要な責務・入出力・依存関係、必要なデータのルールが未決または矛盾していれば、影響する実装を止める。AIの推測で埋めない。
- 止める際は、未決の内容と、このまま進むと何をAIが勝手に決めることになるかを短く示し、解決に必要な質問をする。
- 資料がない、必要な情報が欠けている、または重要な構造上の問題が残る場合も、影響する実装を止めて確認する。未決事項の表が空であることだけで通過させない。
- 決定した契約を変えない関数内部のアルゴリズムや補助関数などはAIに任せてよい。今回の対象外や影響しない未決事項では止めない。独立した作業を進める場合は、未決の判断に依存しないことを確認する。
- 一般的な「実装して」という依頼、沈黙、AIの未確認の提案を、未決事項の解決扱いにしない。判断をAIに任せるという明示的な委任があれば、その範囲内で具体的に決め、内容と委任の事実を資料に記録する。
- 回答で未決事項と関連する要件・設計を更新し、今回の対象範囲について再確認してから進む。
```
